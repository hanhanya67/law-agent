法律咨询 Agent —— 交付说明
==========================

一、先跑起来（三步）
------------------
1. 确认 Python 版本在 3.10 以上
   开始 → 运行 → cmd → 输入 python --version
   低于 3.10 请先升级：https://www.python.org/downloads/
   （代码里用了 int | None 这种写法，3.9 及更早会在启动时报语法错，
     看起来像「代码坏了」，其实是版本不够）

2. 装依赖：在本目录打开命令行，执行
       pip install -r requirements.txt
   核心只有一个 pydantic；要用网页界面再加 fastapi 和 uvicorn。
   装完即可离线运行：页面没有任何 CDN 依赖，字体用系统字体，法条语料在本地。

3. 启动（二选一）
       启动-网页.bat      浏览器打开 http://127.0.0.1:8000
       启动-命令行.bat    纯终端对话
   首次启动会自动建库、自动创建管理员账号，并把一次性密码打印在控制台。


二、两种运行模式：看本目录有没有 .env
--------------------------------------
程序启动时读同目录的 .env：

    有 .env 且 DEEPSEEK_API_KEY 有效 → 在线模式，llm_enabled=true，
                                      答案由大模型生成
    没有 .env / key 为空 / key 失效  → 回放模式，llm_enabled=false，
                                      决策由规则模板给出

两种模式下 Agent 的完整循环都一步不少——

    意图识别 → 查询分解 → 检索法条 → 调用工具 → 观察回灌
    → 定性判断 → 生成答案 → 答案自检 → 写入记忆

唯一区别是「谁来决策」。

回放模式下看到的答案**不代表模型水平**，它演示的是「Agent 是怎么跑起来的」。
这一点在系统里是显式标注的，不是隐藏的：
    · /api/meta 返回 llm_enabled，页面顶部同款显示
    · 评测报告里每条答案都带来源标签（在线 / 回放 / 半回放）
    · 单条答案浏览脚本会先打印来源再显示内容
    · scripts/check_key.py 一次性验 key / 模型名 / Function Calling / 余额
      （返回码 0 = 全过；1 = 硬故障，比如 key 失效或余额不足；
        2 = 有一项没测出结果——模型把 token 预算花在思考上了，
        这一项既不算通过也不算 key 坏了，重跑一次再判断。
        打印「一个正文分片都没收到」时别急着换 key，先重跑。）

想确认自己在哪个模式：启动后看控制台，或访问 http://127.0.0.1:8000/api/meta。

想切到真模型（本目录已有可用 .env 的，跳过这步）：
    复制 .env.example 为 .env
    把 DEEPSEEK_API_KEY= 后面填上你自己的 key
    （另外两个变量 DEEPSEEK_BASE_URL / DEEPSEEK_MODEL 一般不用改）
    重启启动脚本
想退回回放：把 .env 改名或删掉，重启即可。


三、目录结构
------------
    app/        服务端与 Agent 内核（FastAPI）
    static/     前端页面（原生 JS，无框架无 CDN）
    scripts/    辅助脚本：回归测试入口 run_all.py、一次性探针、运维工具
                （其中 split_loose_tasks.py 只在一种情况下用得着：库里还是
                v122 及更早的数据、任务页上有一个叫「历史咨询」的桶把好几种
                法的会话并在一起。默认只预演，加 --apply 才写库，写前自动备份。）
    eval/       评测：run_eval.py（跑）、recompute.py（离线重算）、4 套题库；
                fixtures/ 下是回归用的固定夹具（一张仿工资条 PNG，供
                check_live.py 第 8 节验多模态读图，判据写死为读出 12000）。
                scripts/check_live.py 真 key 下共 10 节 67 项、约三分半，
                第 9 节逐内核验劳动法文案没有串到别的分区，并验偏门问法
                （债务 / 宠物 / 短句）确实先检索再下结论；第 10 节验图书
                馆取原文、在线出题真的走了模型，以及判答引用的条文逐条能
                回库取到（模型编条号会在这里露）；末尾 5 项验在线那张卷子
                的结构（三种题型都在、题面不带答案、报告不预测胜诉率）。
    data/       语料：statutes.jsonl（2066 条条文）、raw/ 下为法条原文；
                domain_statutes.jsonl 为接入内核补录的条文——消保法 63 条、
                食安法 154 条是 gov.cn 抓取的官方全文，道交法 4 条为要点摘录；
                cases.jsonl 为 21 件人社部/最高法劳动人事争议典型案例（离线）；
                region_params.json 为三地社平工资（北京/上海/杭州，含 2024、
                2025 两个年度，算三倍封顶用；可自己加城市或年度）
    README.md   完整设计与踩坑记录

    跑一次全量回归：
        python scripts/run_all.py
    37 个套件，约 3 分钟。


四、值不值得继续追（决策卡）与 MCP
----------------
每轮答案下面会出现一张「值不值得继续追」决策卡，只回答一个问题：这趟要不要继续往下走。
五格依次是：

  ① 时间成本 —— 受理与裁决的法定期间、进入诉讼后的周期；
  ② 经济成本 —— 哪些环节收费、哪些成本要自己扛；
  ③ 历史成败案例 —— 本地已核验相似案件里支持 / 部分支持 / 驳回各几件，
     附案例名；完整官方「处理结果」原文在下方附录；
  ④ 收益比较 —— 本轮核定的可得金额 vs 要投入的时间与费用。金额没核定
     时留空 ＿＿＿＿；小额争议会明说「可得约几百元，划不来」；
  ⑤ 建议上不上诉 —— 直接给结论（建议上诉 / 不建议上诉 / 建议先补材料 /
     建议先核时效），结论下面写清依据：已核算金额、法定期间、凭证状态。
整张卡是规则生成的，不需要模型、不额外花钱、不联网，回放模式下照样有；
不给胜诉率，卡面只留一句「仅供参考，不构成法律意见。」。

下面「更多材料」可展开，里面是原来的五块（同样是纯规则产物）：

  · 程序时间轴：从时效起算到申请执行，八个阶段，每个都写清法定期间
    和依据条号。起算日没核算过时只列阶段，绝不编一个具体日期。
  · 仲裁请求事项（候选）：按案情列出可勾选的请求，金额一律留空 ＿＿＿＿，
    默认一条都不勾。勾中的可以用「复制勾中的请求事项」粘到你自己的
    申请书里——系统不会替你写进文书，docgen 生成的仲裁申请书里
    请求事项 / 金额 / 条号仍然是留空的。
  · 举证体检：谁举证、要准备哪些材料、还差什么。单位掌握的材料
    （考勤、工资台账等）可以申请仲裁庭责令提供。
  · 判例参考与申诉决策：从本地收录的典型案例里找相似案件，列出
    支持 / 部分支持 / 驳回各几件、每件附官方「处理结果」原文与来源，
    再把仲裁耗时、费用、可得金额并排摆出来。**不给胜诉率、不预测结果、
    不替你决定要不要申诉**；可得金额那行也留空，由本人核定。
  · 显式画像：由你自己选立场（职工 / 单位 HR / 代理人 / 只是了解），
    系统**不根据语气或用词判断你的身份**。语气识别只给「要不要用简洁
    表述」的建议，且默认不生效，勾了确认才应用；它只影响显示方式，
    绝不改答案、定性、金额、条号。

决策卡下方「按当前会话重算」：改完「案情档案」或切换立场后点一次即可，
不必重新问一句。对应接口是 POST /api/case/extras，只认自己的会话/任务。

MCP（给外部 Agent 客户端调用）：
  · 配置示例在根目录 mcp_config.json，把 cwd 改成你解压的绝对路径。
  · 命令 python -m app.mcp_server，走 stdio，不需要 key、不联网、只读；
    不接触账号、历史会话、个人档案。
  · 6 个工具：search_statutes / get_article / calculate_compensation /
    calculate_deadline / case_analysis / case_decision。
    前两个 case_* 分别返回「答案附录五块」和「判例参考 + 成本收益卡」。
  · 本机自检：python -m app.mcp_server --self-check（六项）
  · 回归：python scripts/test_mcp.py（57 项）、
          python scripts/test_extras.py（96 项）、
          python scripts/test_cases.py（58 项）、
          python scripts/test_persona.py（63 项）、
          python scripts/test_network.py（76 项）、
          python scripts/probe_network_live.py（14 项，真起服务验开关全开）


五、这一版新增：判例参考与显式画像（v117）
------------------------------------------
判例库是 `data/cases.jsonl`，收录人社部与最高法联合发布的劳动人事争议
典型案例第二、三、四批共 21 件（14 支持 / 3 部分支持 / 4 驳回）。
页面会如实标注「本地判例库，未联网」，每件案例都能点开看官方处理结果
原文和来源链接。要换库：改 `scripts/build_cases.py` 重新生成即可，
条号必须能在 `data/statutes.jsonl` 查到，回归会逐条核。

为什么没有「胜诉率」：典型案例是被挑选出来的，不是随机样本；系统也
看不到你的证据原件。给一个百分比是伪精确，还会和「仅供参考、不构成
法律意见」自相矛盾。所以这里只给可核验的结局计数，样本少于 3 件会
明确写「相似案件不足，不足以说明任何倾向」。

联网在 v118 已补全：系统会自动检测有没有网络，无网自动降级回本地判例库。
要真的联网检索按下面第六节配置；默认一次外部请求都不发。判例库本体
始终离线可核验，外部结果永远只作线索、不作结论。

成本收益卡回应的正是「可能要好几个月，最后赔款刚好够交律师费」：
时间（受理 5 日 / 裁决 45 日可延 15 日 / 收到裁决书 15 日内起诉）、
费用（劳动争议仲裁不收费）、可得金额并排列出，最后直接给结论：
金额够、期间没风险就建议上诉，金额不够覆盖投入就写「划不来」。

只要判例卡、不想拉整包时：POST /api/case/decision，参数与
「按当前会话重算」一致，返回的就是办案包里那一块，结构和 MCP 的
case_decision 完全相同。归属校验与显式立场两边共用同一段代码，
不会出现「网页一个口径、MCP 另一个口径」。要调相似案件条数，用
MCP 的 case_decision 带 limit（1–8）。


六、这一版新增：网络自动检测与受控联网（v118）
----------------------------------------------
打开页面，判例卡里会写「网络（自动检测）：…」。服务启动时后台做一次
TCP 握手（默认目标是 DEEPSEEK_BASE_URL 的主机），只握手不发包、不带任何
提问内容，结果缓存 300 秒；没探完之前一律保守按离线处理，绝不让第一个
提问的人干等 DNS。DNS 失败、超时、被拒都归成离线，不会把异常抛进答案。

三条边界，比「能联网」更要紧：
  · 自动检测 ≠ 自动联网。默认包放在有网机器上也不会往外发请求。
  · 无网自动降级。允许了外部检索但检测不到网络时，判例卡写明
    「已自动跳过」，21 件已核验案例一件不少、结局计数一个不变。
  · 外部线索不进结论。点「联网补充线索」才发请求，结果单列一块、
    每条标「未经本地核验」，不进相似案件、不参与结局分布、不改金额
    与条号；含胜率百分比或「建议申诉」字样的整条丢掉。

怎么真的开起来（都在 .env 里）：
  1. CASE_SEARCH_ADAPTER=1                 —— 允许外部检索
  2. LAW_CASE_SEARCH_URL=https://你的检索服务/?q={q}
     只认 {"items":[{"title","url","snippet"}]} 这种 JSON，不猜网页 DOM。
     没配会明说「未配置检索源」，不会假装搜过；只允许 https。
     （官方源没有稳定的公开检索接口，硬编某个网页的 DOM 只会变成
       「看着能用、其实永远解析失败」，所以这里留可插拔入口。）
  3. 在判例卡点「联网补充线索」，或 POST /api/case/decision 带
     {"external":1}。SSE 答案流与 MCP 服务永远不联网。
  也可以不配 URL，用 websearch.register() 注入自己的适配器。

调试用：
  · LAW_NET_MODE=auto（默认）/ online / offline，后两个是强制模式、
    不探测，给演示和回归用。
  · LAW_NET_PROBE_HOST / _PORT / LAW_NET_TIMEOUT_MS / LAW_NET_TTL 可调
    探测目标、超时与缓存。
  · GET /api/network 看当前结论，带 ?refresh=1 才同步重探一次。
    /api/meta 和 /api/status 也带 network 字段（公开页只给结论）。

回归：python scripts/test_network.py（76 项）验模块层；
python scripts/probe_network_live.py（14 项）真起一次服务、把
CASE_SEARCH_ADAPTER=1 与 LAW_NET_MODE=online 全打开，用本机回环的临时
HTTP 服务冒充检索源，证明 external=1 真能拿回线索、含胜率的条目在服务层
也被丢掉、相似案件仍是本地 4 件、不带 external 就不联网。两个脚本都进了
run_all，全程不碰外网；三处篡改自检（放开胜率过滤 / 改离线文案 /
让探测阻塞）分别会红 7 / 2 / 3 条。


七、多领域内核：一个引擎，五个法律领域（v119–v123）
----------------------------------------------------
这一版把系统从「劳动法问答」扩成「多领域法律咨询平台」。
劳动法只是其中一个内核，而且是功能最全的那个。

五个内核（首页直接选，选定后绑定本次咨询）：

  内核          语料                        专属能力（别的内核做不了）
  ----------------------------------------------------------------
  劳动用工      378 条（劳动法 / 劳动合同法 /   经济补偿与二倍工资测算、
                解释一·二 / 调解仲裁法 /        仲裁时效倒计时、仲裁申请书生成、
                工伤保险条例）                  9 个工具
  消费·食安     消保法 63 条 + 食安法       退一赔三 / 价款十倍 / 损失三倍
                154 条，均为官方全文         择一，保底 500 与 1000 元
  民法典·合同   1688 条（民法典 1260 +       合同效力核查、违约金调整、
                合同法 428，含已废止版）      新旧法条号衔接（114 → 585）
  道交·人损     民法典侵权责任编 + 道交法     十个赔偿项目逐项核对、
                第 76 条等 4 条摘录             交强险分项限额与赔付顺序
  婚家·继承     民法典婚姻家庭编 + 继承编     共同财产 / 共同债务 / 抚养权 /
                （零新增语料）                继承顺序 / 遗嘱要件七项核对

为什么「换内核」不等于「换提示词」：
v118 的答案链路上有六处把劳动法写死了——提示词、定性规则表、案情槽位、
专用计算、办案包五块、意图边界。v119 把这六处收敛成一个 LawProfile
（app/profiles.py），一个内核 = 一份配置 + 一份语料，引擎代码一行不改。
接入内核的办案包与劳动法**结构同构**（五块 + 一块 domain），
所以前端渲染函数一行都不用改。

三条硬规矩：
1. 劳动法必须是默认内核，且默认路径逐字保持 v118 的行为——老套件里有
   「恰好等于五块」「提示词逐字比对」这类断言，多一个键、多一个字都会红。
2. 内核只能显式选，不能从提问猜。猜错内核等于拿劳动法条文去答食品安全
   问题，比答不上来更糟。非法取值一律回落劳动法，不「就近找一个」。
3. 会话绑定，不搞全局开关。两个标签页可以一个问工资、一个问离婚。

为什么内核切换顺便收窄工具表：超过 10 个工具模型选错率显著上升。
劳动法 9 个，其余内核各 5 个通用工具。

每个内核在界面上是「自己的界面」，不只是换几行字（v121–v122）：
顶栏第二行是一条常驻索引，五个内核各有一枚印章字（劳 / 食 / 民 / 道 / 家）
和自己的颜色。点一下，整页纸色、主色、印章、四条示例问题一起换：

  内核        浅色纸            主色
  ------------------------------------------------
  劳动法      象牙 #f6f1e6      朱红
  消费·食安   竹青 #edf3ea      墨绿
  民法典·合同 素笺 #edf1f7      靛蓝
  道交·人损   麻纸 #f7f0e1      赭黄
  婚家·继承   云母 #f3eef7      藕紫

暗色模式每个内核另有一套（不是把浅色调暗，是各自一套暖底）。
换的不只是强调色——背景、卡片、分隔线、顶栏一起换，否则切过去整页还是
同一张米黄纸，看起来「只换了颜色」。
顶栏右侧那个开关管日读 / 夜读（快捷键 Ctrl+J）：左浅右深，滑块颜色跟着
当前法域走。只有这两档，也不看系统的配色偏好——没选过就是日读，选过就只
认你最后点的那个值。以前那档「跟随系统」在开关上表达不出来，实际用起来
常变成「我明明选了夜读，第二天早上自己变回日读」。
原生部件（滚动条、下拉箭头、日期面板、自动填充底色）的颜色由 color-scheme
决定，它**不看**主题属性，不声明就跟系统走——日读页面配一条深色滚动条，
看着就像还在跟随系统。v130 起两档都显式钉死，跟随系统的最后一条视觉路径
也断掉了。设置里那行「配色」现在直接写当前档位（日读 / 夜读），只有两个。
「只有两档」还不只是脚本里的规矩：三个页面的样式表之前都放了一行内联脚本，
在首帧之前就把 data-theme 定下来（只读本地存的值，不看系统）。以前那行写在
页面末尾的 ui.js 里，晚了几十毫秒——选了夜读的人每次刷新都先看到一道白光。
换主题那一趟，旧帧是**完全不动**的：只有圆在长，圆外面那一圈颜色和亮度一点
变化都没有（v131 之前旧帧会先淡到 88% 再被圆盖掉，看着像整页闪一下）。

换法是一个从画面中心扩散的圆（v128）：点索引条上的某一部法，圆心在屏幕
正中间，圆向四周同时铺开，把整页刷成这部法的纸色，约 0.6 秒（暗色下
0.7 秒——深色纸之间的明度差更小，不多给一点时间就看不出边界）。
浅色下这圈边上有一道很细的主色描边，圆推进到哪儿一眼能看见；暗色下不给
描边，靠压暗旧页面来显边界。圆铺满就结束，不再有多余的收尾动作——v129
删掉了原来那一记「整页上浮 6px」，圆到边之后画面已经静止，再挪一下就成了
多余的抖动。
换法的整条链路里没有任何「收尾动作」（v129 删了 6px 上浮），过场期间也不会
再启动平滑滚动（v130 改成直接跳）——滚动会一直滑到圆铺满之后，看起来就是
画面停了还在动。两项叠加起来，切完就是静止的。
不支持这个浏览器特性的环境、以及系统里开了「减少动效」的用户，直接换色。
不用担心盖不满：半径按「视口对角线的一半」算，四角正好压到。

任务也按它自己的法上色（v122）：任务卡上有法域徽章（印章 + 简称），
卡片左侧色条、底色、按钮都跟着那件案子属于哪部法走，和当前页面上选中的
内核无关——一张劳动纠纷的卡永远是朱红，哪怕你正在看食安。点「进入」时，
整个页面也会切到那件案子的法域。

为什么切内核会顺手开一次新咨询：会话的内核在服务端是不可变的，
POST /api/chat 只要有 session_id 就用库里绑定的内核，前端传的 profile
会被忽略。不新开就会出现「页面是食安配色、答案还是劳动法条文」——
那比不让切更糟。原对话不会丢，它在历史记录里。

任务会自动生成（v123）：空对话里问第一句，服务端就建一个任务，标题取第一句
提问（「请问一下，公司拖欠工资三个月了，我该怎么办」→「公司拖欠工资三个月了，
我该怎么办」；寒暄另算，叫「劳动用工咨询」）。顶部随即出现当前任务条，

原样留在「任务」页——不会再把劳动法的会话塞进食安法的案子里。
老库里已经并进「历史咨询」的会话不会自动拆开（那是历史），
想清理的话在「任务」页删掉或归档即可。

界面上不再有说明书（v122）：「条文 2066 条 · 9 部法律 · 引用边 175 条 ·

为什么没有刑法内核：
能公开抓到的刑法全文是 1997 年修订版，缺 12 个修正案——没有袭警罪、
高空抛物罪、催收非法债务罪，刑事责任年龄还停在 14 周岁。拿它答刑事
问题比不答更糟，所以宁可不开这个内核，也不拿过期法条凑数。

为什么消费·食安的语料要补成全文：
v119 时这个内核只有 8 条要点摘录——问「预付卡跑路能退款吗」，摘录里没有

食安法 154 条从 gov.cn 抓成官方全文（抓取脚本要求条号从 1 连续到 N，
对不上一个都不写），检索实测：预付卡跑路 → 消保法第 53 条；
标签瑕疵 → 食安法第 148 条；七日无理由退货 → 消保法第 25 条。
道交法仍是 4 条摘录（第 70/73/76/77 条），界面和本说明里都写作「摘录」，
不冒充全文。全文与摘录是两件事，混着说就是新的假话。

十一、这一版新增：成本给区间、把联网能力说清、三层记忆（v137）
----------------------------------------------------------------
1. 时间与费用不再是「以受理机关为准」这种等于没说的话，改成三级：
     A 类  法定、条号在包内   → 直接给数并引条号
           例：受理 5 日内决定（调解仲裁法第二十九条）、45 日内裁决
           可延 15 日（第四十三条）、仲裁不收费（第五十三条）
     B 类  法定、但法未随包   → 给数或区间，并标「未随包，可自行核对」
           例：一审 3–6 个月、二审 3 个月；诉讼费 1 万元以下每件 50 元、
           1–10 万元部分按 2.5%（按标的额分段累计算给你看）
     C 类  无统一标准         → 只给行情区间
           例：代理费常见 3000–10000 元起，或按标的 10%–20%
   金额仍然只来自你自己的核算；能算出金额时，卡片会直接写「可得约
   N 元、诉讼费约 M 元、扣掉成本后仍有剩余 / 划不来」。
2. 判例格拆成两行，不再用「本内核没有本地典型案例」一句话把能力说没：
     · 本地已核验：0 件。
     · 联网查公开案例：未开启（开启后可在此看到线索）。
   开启检索源后变成「联网线索 N 条（未核验，只作线索）」。外部结果
   不进本地计数、不进结论——内外分开，不是合并。
3. 记忆分三层，解决「聊到第十轮忘了第二轮的诉求」：
     · 任务目标（goal）：一句话写清这个案子要办什么，显示在任务卡第二行；
     · 滚动摘要（summary）：诉求 / 已确认事实 / 已排除方向 / 还没答的问题，
       每 4 轮重写一次，金额以你最新说的为准（改口就覆盖）；
     · 最近六条原话：跟着摘要一起作为下一轮的背景。
   这两样只注入劳动法以外的四个内核；劳动法的提示词一个字没动。
4. 档案页多了「系统记下的（可删）」：系统只记你明确说过的城市、职业、
   单位性质，每条都附你当时的原话，旁边一个「删掉这条」。不做任何推断。

test_cases.py 60 项、check_ui.py 205 个断言调用点；快照清单 68 个文件与工作区
逐字节一致。


十二、法典图书馆 / 自主学习 / 个人主页（v139 起，v140 大幅增强）
------------------------------------------------
1. 切换法案的入口**只在「智能咨询」页**。任务、时效、文书、档案、历史、
   案情档案以及下面三个新页面都收起顶部索引条；JS 入口另有一道闸，
   键盘或程序调用也绕不过去。三个新页面顶部有「页内法典选择器」，
   它只决定本页看哪部法，**不改变当前咨询绑定的法域**。

2. 法典图书馆：按所选法典查看本地收录的条文原文。左侧目录按章分组、
   点条号直接跳到原文；顶上输入框支持「第 585 条」这类条号直达，
   也支持关键词检索（只在本内核语料里搜）。道交法 4 条明确标为
   「要点摘录」，不冒充全文；已废止条文带状态标记。

3. 自主学习：**一次生成一整张卷子**。先选出题范围（全部 / 指定章节）和
   题数（5 / 10 / 15 / 20，或自填 1–30），再定题型配比（单选 / 判断 /
   填空），点「生成试卷」就开始答。**三种题型都不需要联网**：单选题的
   选项与答案、判断题的真假条号、填空题的挖空位置与答案，全部由服务端
   从语料里算出来，模型最多只帮忙写中文题面。填空题判分是宽容的——答
   「三十日」「30日」「30天」都算对，答得啰嗦但只要包含了答案也对。

   答的过程顶部有进度条和题号导航，可以随时回头改。答完点「交卷」，
   逐题判完后出一份**本次评估报告**：卷面得分、各题型得分、章节分布
   （都画成图）、逐题回顾（错在哪、正确依据是第几条），最后给一句
   「下一步该练什么」。报告可导出 .txt。

   判分只有一条路径：交卷不重判，每题仍走原来的判答接口落库。所以
   「卷面得分」永远等于「逐题判对的比例」，不会出现卷面分和错题集对不上。

4. 个人主页分六个子页：概览 / 学习进度 / 知识树 / 错题 / 徽章 / 打卡。
   顶部一排子标题，点哪个就只显示哪个（同一时刻只有一个子页），选中项
   记在本机，下次进来还是那一页。概览页四张图：
     · 近 30 天答题趋势（折线）
     · 五部法答题量占比（环形）
     · 五部法掌握度（雷达）
     · 最近几次卷面得分（柱状）
   「学习进度」页一次列全五个法典的进度（章节覆盖率 70% + 答题正确率
   30%，各法典独立算），每张卡三行读数（章节 / 已练 / 正确率）+ 一颗
   「去练这部法」按钮；「打卡」页是自然月日历，可翻到上个月看断档。
   个人知识树画成真正的树：中间是法典印章，往右长出每部法的主枝，
   再往右挂章节叶片，枝与叶之间有连线，进来时线会一段段「描」出来。
   树可以按法典切换，五棵树都能看；还没练过的法也会画出骨架，枝上
   挂着「还没练过」，让你看见还有多少枝没长出来。鼠标停在任一节点上，
   根到它的那条枝会整条亮起、其余压暗。
   手机上这棵树不缩成缩略图：它保持原尺寸铺在卡片里，卡片内可以左右
   滑动看全（按屏宽等比缩小的话，11.5 号的章名只剩 4 像素高，等于没画）。

   学习徽章共 21 枚、分六组（累计 / 坚持 / 精通 / 卷子 / 广度 / 错题），
   点进这一页直接摊开，未解锁的也显示，带进度条（例如「连续 7 天」
   完成 3/7）；右上角「收起」可以把整面墙折起来，再点「展开全部」放回。
   错题集按遗忘
   曲线安排复习：错 1 次隔 1 天再看、2 次隔 3 天、
   3 次以上隔 7 天，今天该复习的会单独提示；错题可以一键「重新组卷」，
   卷子里的题和当初错的完全一样，分数才可比。

十三、常见问题
------------
Q：页面打开是空白 / 一直转圈
A：先看启动窗口有没有报错。最常见是依赖没装全（缺 fastapi 或 uvicorn）。

Q：提示端口被占用
A：两个启动脚本（启动-网页.bat / 启动-命令行.bat）启动时会先查端口，被占用就
   直接退出并告诉你占用方 PID，不会悄悄起一个连不上的服务。
   要换端口：主要启动方式是双击 .bat，改对应 .bat 里的 `set "PORT=8000"` 即可；
   只有用 `python app/server.py` 直接起时才改 server.py 里 uvicorn.run 的 port
   （它现在也读 PORT 环境变量，和 .bat 是同一个来源）。

Q：答案明显不对
A：先确认是不是回放模式（页面顶部或 /api/meta 的 llm_enabled）。
   回放模式下的答案是模板，本来就不该当作法律意见。

Q：这是法律意见吗
A：不是。这是课程项目级别的演示系统，答案仅供参考，不构成法律意见。
