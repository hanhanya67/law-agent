eval/fixtures —— 回归用的固定夹具
==================================

pay_slip.png
    一张仿工资条（620×420 纯文字图），内容固定：

        姓名    张伟
        部门    生产部
        工资期间 2026年8月
        基本工资 8,000.00
        岗位津贴 2,500.00
        绩效奖金 1,500.00
        应发合计 12,000.00      ← 断言锚点
        代扣个税 290.00
        实发工资 11,710.00
        单位：某某制造有限公司

    用途：`scripts/check_live.py` 第 8 节拿它验「多模态真能读图」。
    期望 monthly_wage = 12000，且模型要能指出「图上没有社保/扣款构成」
    （那是 unreadable 字段，不是漏读）。

    为什么图跟着包走、而不是运行时用 PIL 现画：
      · 现画依赖 PIL，而 requirements.txt 里只有 pydantic + fastapi，
        收货方多半装不到；夹具随包发，验的时候零依赖。
      · 图固定，判据才能写死成「必须是 12000」。现画的话字体一换、
        换行一变，读出来的数就不是这个，断言会变成时绿时红。

    人名与单位都是虚构的，不指向任何真实主体。

make_pay_slip.py
    上面那张图的生成脚本（「这张图从哪来的」的答案）。平时不用跑。
    需要 PIL（pip install pillow），刻意不进 requirements.txt——应用本身
    不需要它，只有重新生成夹具才需要。
    跑它之前先想清楚：check_live.py 断言的是 12000 与 doc_type=pay_slip，
    改了数值或版式就要同步改断言，否则第 8 节会红（那是断言在正常工作）。
